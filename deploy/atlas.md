# MongoDB Atlas M0 (free): the source of truth

Render's disk is wiped on every restart/deploy, so **Atlas holds everything**: state (desired/mode),
config versions, journal, account snapshots, fills, monitor summaries, audit log, the user account,
revoked tokens and cloud settings.

Facts checked 2026-10-12 against <https://www.mongodb.com/docs/atlas/reference/free-shared-limitations/>:
- 0.5 GB storage (data + indexes). One free cluster per project.
- 10 GB in / 10 GB out per rolling 7 days.
- **Inactive free clusters are paused after 30 days** (older pages say 60; the plan says 60 —
  the current docs say 30). Not an issue while the runner connects constantly; Atlas e-mails 7 days
  before pausing. A paused cluster must be resumed in the Atlas UI.
- Connection limit: *verify* on the same page (a single-worker service uses only a handful).

## Steps (one time)

1. Sign up at <https://www.mongodb.com/cloud/atlas/register> (free; no card for M0 — *verify*).
2. Create a **project** (e.g. `kalshi-control`).
3. **Create cluster** → **Free (M0)** → provider **AWS**, region **N. Virginia (us-east-1)**
   (same area as the Render `virginia` region) → name `kalshi` → Create.
   Untick "load sample data".
4. **Database Access** → **Add New Database User**
   - Authentication: Password. Username e.g. `kalshi_app`.
   - Click **Autogenerate Secure Password** (long, letters+digits only, so no URL-encoding trouble). Copy it.
   - Built-in role: **Read and write to any database** (or, tighter, a custom role with `readWrite`
     on the `kalshi_control` database only).
5. **Network Access** → **Add IP Address** → **Allow access from anywhere** (`0.0.0.0/0`).
   - Why: Render free has no static outbound IP; outbound traffic uses shared per-region ranges
     (Render docs: "shared across all services in the same region"). Allow-listing those ranges would
     also admit every other Render customer in that region, so it's not real protection either.
   - Trade-off: the cluster is reachable from the internet, so **the password is the only lock.** Use the
     autogenerated one, keep it only in the Render env (and your PC's shell when bootstrapping), and
     rotate it if it ever leaks. TLS is always on for Atlas.
   - On the optional VM path you can instead allow-list just the VM's static IP and delete `0.0.0.0/0`.
6. **Connect** → **Drivers** → Python → copy the `mongodb+srv://...` string. Replace `<db_password>`
   with the password. That is `MONGODB_URI`. The database name is set separately (`MONGODB_DB=kalshi_control`);
   the API creates collections and indexes itself on startup.
7. Put `MONGODB_URI` in the Render dashboard (service → Environment). Never in git, chat, or the app.

## Bootstrapping the owner account (on your PC, not on Render)

Render free has no shell, so the one-time user creation runs locally against Atlas:

```powershell
cd <repo>
python -m pip install --require-hashes -r control_api/requirements.txt   # hash-pinned lock (works on Windows too)
python -m control_api.auth.bootstrap --gen-keys          # prints JWT_SECRET, TOTP_ENC_KEY, TICK_TOKEN
$env:MONGODB_URI = "mongodb+srv://..."                    # same value as on Render
$env:TOTP_ENC_KEY = "<the TOTP_ENC_KEY you put on Render>"
python -m control_api.auth.bootstrap --username <you>    # prompts for password twice, shows QR once
Remove-Item Env:MONGODB_URI, Env:TOTP_ENC_KEY            # or just close the window
```

Scan the QR code with an authenticator app (Google Authenticator, Aegis, 1Password...). It is shown once.
Your PC's IP is covered by the `0.0.0.0/0` rule.

## Useful afterwards
- **Metrics / Collections** tab: check storage stays well under 0.5 GB (journal and heartbeats are small;
  high-volume collections such as heartbeats should have TTL indexes; see docs/ARCHITECTURE.md).
- **Backups:** M0 has no automated cloud backups (*verify*). If you want a copy, use the Atlas UI export or
  `mongodump` from your PC occasionally.
