# Shadow mode: sprint contract (2026-10-17)

Single shared source for every agent in this sprint. If something is unclear, build the simplest thing that satisfies it and note the choice in your report. Do not edit this file (ask the lead).

**Goal.** While the bot runs, record what the installed strategy WOULD bid on real production markets (public, unauthenticated reads only), estimate whether those hypothetical bids would have filled, score them with real settlement results, and show an **estimate** page. Shadow mode places no orders and cannot: it has no credentials and no order code path.

**Hard rules.**
- No strategy logic in this repo. Shadow calls the installed strategy's own `desired_quotes` (see below). The stand-in returns an empty list. Never write the strategy's selection rules, real cells, real tickers or research numbers into any file here. Test fixtures use `KXDEMO*` tickers.
- Stop must never wait on shadow: its own thread, its own timeout, never the pass lock, env lock, fence or Stop pool.
- Work on branch `feat/shadow-mode` in `maker-console/`. Agents never commit and never merge.
- Tests parallel-safe; mark tests over ~1 s `@pytest.mark.slow`.

## Strategy interface (installed `kalshi_bot.maker_strategy`)

- `Quote` with fields `ticker, side, price, count, book_side, order_price, cell` (plus a `cost` property).
- `desired_quotes(markets, books, now, max_order_dollars, budget) -> list[Quote]`: pure, no I/O.
- Stand-in (`kalshi_bot/maker_strategy.py` here): define `Quote` (a dataclass with those fields and `cost`) and `desired_quotes(...)` that **returns `[]`**. With the stand-in installed, shadow records nothing and the page says so (`standin: true`).
- `scripts/overlay_private.py` `check_contract`: after overlay, the module must expose `desired_quotes` with exactly those 5 parameters and `Quote` with those fields, else exit 3.

## Store methods (async; MemoryStore and MongoStore, same behaviour)

Collections `shadow_episodes` and `shadow_passes`, TTL 30 days on `ts`. Episode `_id` = `ep_id` = sha256 hex of `ticker|book_side|order_price|join_ts_iso`; writes are idempotent upserts by `ep_id`. Dates are timezone-aware UTC datetimes.

- `shadow_upsert_episodes(docs: list[dict]) -> int`: upsert by `ep_id`, `$set` all given fields.
- `shadow_open_episodes() -> list[dict]`: episodes with `end_ts` null.
- `shadow_ended_unread(limit: int) -> list[dict]`: `end_ts` set and `trades_read` false, oldest first.
- `shadow_unsettled(now, limit: int) -> list[dict]`: `result` null and `close_time <= now`, oldest first.
- `shadow_settled(since) -> list[dict]`: `result` set and `settled_ts >= since`.
- `shadow_recent(limit: int, state: str|None) -> list[dict]`: newest first by `join_ts`; `state` in `open|ended|settled|None`.
- `shadow_count_new_since(ts) -> int`: episodes with `join_ts >= ts`.
- `add_shadow_pass(doc: dict) -> None`, `shadow_recent_passes(limit: int) -> list[dict]`.
- `get_shadow_summary() -> dict|None`, `set_shadow_summary(doc: dict) -> None`: one cached doc.
- Cloud settings gain `shadow_enabled: bool` (default false), validated as bool, saved through the existing `PUT /api/cloud` (audited; no 2FA needed because shadow only reads).

Episode document fields: `ep_id, env("prod"), ticker, series, side, book_side, price, order_price, count, cost, cell(list), close_time, join_ts, last_seen_ts, end_ts|null, end_reason(cancel|closed|shadow_off|stale)|null, q0, level_min, level_last, n_obs, trades_read(bool), traded_vol, through(bool), through_ts|null, truncated(bool), fill{lo,mid,hi}|null, result("yes"|"no")|null, settled_ts|null, pnl{zero:{lo,mid,hi}, maker:{lo,mid,hi}}|null, standin(bool), ts`.
Pass document: `ts, ok, duration_s, markets, books, quotes, new_eps, ended_eps, trade_reads, settled, truncated(bool), errors(list of exception type names only)`.

## Pure model API (`services/shadow_model.py`, no I/O, deterministic)

- `fill_scenarios(q0, level_min, traded_vol, through, count) -> {"lo","mid","hi"}` in contracts, each capped to `count`: lo = `count` if through else `clamp(traded_vol - q0, 0, count)`; hi = `count` if through else `clamp(traded_vol - a_min, 0, count)` with `a_min = min(q0, level_min)`; mid uses `a_mid = (q0 + a_min) / 2`.
- `maker_fee(count, price, mode)`: mode `"zero"` -> 0.0; mode `"maker"` -> `ceil(0.0175 * count * price * (1 - price) * 100) / 100`.
- `episode_pnl(fill, price, win, fee) -> float` = `fill * ((1 if win else 0) - price) - fee`.
- `score_episode(ep) -> {"zero":{lo,mid,hi},"maker":{lo,mid,hi}}` using `ep["fill"]`, `ep["price"]` (price paid per contract), `ep["result"]` vs `ep["side"]`.
- `summarize(episodes, now, *, seed=7, draws=2000) -> dict`: aggregates settled episodes into the summary shape below with a day-clustered bootstrap 90% interval on the central scenario (resample settlement days with the fixed seed); `too_early` is true until at least 7 settled days and at least 30 central fills.

## Runner integration (backend)

- New task `runner-shadow` started in `start()` only when `runner_enabled` and (`SHADOW_ENABLED` env true AND cloud setting `shadow_enabled` true). Own `ThreadPoolExecutor(max_workers=1, thread_name_prefix="shadow")`. Cycle every `poll_minutes` offset by half an interval. Skipped when not leader, or while `_strategy_running`, `_stopping`, `running_pass` or `_shutting_down`. Wrapped in `asyncio.wait_for(..., SHADOW_BUDGET_S=60)`; a timeout discards the partial result and writes nothing half-done. Never takes `_pass_lock`, `_ENV_LOCK`, the fence or the Stop executor. Shutdown cancels it without waiting. Runs whether the bot is running or stopped.
- Constants: `SHADOW_BUDGET_S=60`, `SHADOW_MAX_BOOKS=150`, `SHADOW_MAX_TRADE_READS=40`, `SHADOW_DAILY_NEW_CAP=1500`. Truncation is recorded in the pass doc and shown.
- Read-only client in `services/shadow.py`, three independent layers: (1) `ReadOnlyMarketData` by composition exposing only `markets(series, status, min_close_ts=None)`, `orderbook(ticker, depth)`, `market(ticker)`, `trades(ticker, min_ts, max_ts)`; no `request`, `create_order`, `cancel_order`, `get_balance`, `get_orders`, `get_positions`; (2) `GetOnlySession(requests.Session)` raising `PermissionError` on any non-GET and on any path outside `/markets`, `/markets/{t}`, `/markets/{t}/orderbook`, `/markets/trades`; (3) client built with no key id and no private key, never via `from_env`, `mode_keys` or `kalshi_env`. A `shadow_factory` is injectable into `Runner(...)` (tests pass fake transports); shadow never receives the trading `kalshi_factory`. Prod public base URL from `kalshi_bot.config.BASE_URLS["prod"]`.
- Episode lifecycle per cycle: fetch markets and books for the configured series; call the installed `desired_quotes` per series with the budget split the same way the public settings describe it (run budget divided evenly across series, per-order cap = the smaller of max order and the per-series share); diff the desired keys `(ticker, book_side, order_price)` against open episodes (unchanged key = same episode; new key = new episode at the back of the queue; missing key = ended with `cancel`; closed market = `closed`); read trades once per ended episode (reuse `queuepos` / `fillquality` helpers where they fit); settle episodes whose market has resolved (market `result`); write a pass doc; refresh the cached summary with `summarize`.

## Sprint 2A-2 additions (2026-10-21; additive, existing fields and estimate math unchanged)

**Per-day view (S2).** The summary gains `by_event_day`, `day_stats` and `reliability_note`. A "day" is the UTC date of `settled_ts` (else `close_time`), the same key as `daily`; for daily markets that is usually the day after the event date.
- `by_event_day`: `[{"day", "episodes", "filled_episodes", "cost": {lo,mid,hi}, "pnl": {lo,mid,hi}, "return": {lo,mid,hi}|nulls}]`, oldest first. `episodes` = scored episodes, `filled_episodes` = central fill > 0, cost = fill x price per scenario, pnl uses the maker fee, return = pnl / that scenario's cost (lo/hi are the min/max like the headline; null when there was no fill).
- `day_stats`: `{"event_days", "days_with_fills", "filled_episodes", "mean_return_mid", "sd_return_mid" (sample, null under 2 days), "worst_day"|null, "best_day"|null ({"day","return_mid","pnl_mid"}, by central return), "best_day_pnl_share", "top3_pnl_share"}` (shares of total central P&L, null unless it is positive).
- `reliability_note`: the app's too-early sentence plus the counts, while days with a fill < 7 or filled episodes < 30; null after.

**Arbitrage shadow scan (S3).** Off unless the env var `SHADOW_ARB=true` (read each cycle; never on with the stand-in installed). At most one scan per shadow cycle, run last inside the worker, through the same `ReadOnlyMarketData` (GET-allowlisted, no credentials) using only `markets` and `orderbook`, and the installed scanner's pure `best_opportunity(event, books, max_contracts)`. It never calls the scanner's scan, log or order functions and writes no file. Budgets: `SHADOW_ARB_MAX_REQUESTS=60`, `SHADOW_ARB_BUDGET_S=15` (checked before every market-list and order-book read; no read starts unless a worst-case slow read, `SHADOW_ARB_READ_RESERVE_S` = client timeout x attempts = 16 s, still ends before the cycle deadline), `SHADOW_ARB_MAX_EVENTS=40`; the series start rotates each minute so capped scans still cover every series. Exceeding a budget stops the scan and records `skipped` (`request_budget|time_budget|event_budget|error`); it never discards the cycle's episode work. The pass doc gains `arb_opps` and `arb_skipped` only when a scan ran. Settings come from the arbitrage settings (`arb_series`, `arb_max_contracts`, `arb_min_profit`, and `arb_scan_cap` for the gate check).
- Storage: inside the cached summary doc under `arb` (no new collection): `{"days": [{"day", "scans", "skipped", "requests", "dropped", "events": [{"event", "kind", "first_seen", "last_seen", "seen", "seen_yes", "seen_no", "profit", "cost", "contracts", "legs", "gate_ok"}]}], "last_scan"}`; 30 UTC days kept, at most 300 events a day (`dropped` counts the rest). The runner folds each scan in right after the pass doc and carries the block over on every summary refresh.
- Served (`arb` in the summary): `{"enabled", "days": [{"day", "opportunities", "yes", "no", "profit", "median_cost", "gate_pass_share", "median_duration_s", "scans", "skipped", "dropped"}], "rolling": {"7d"|"30d": {"from", "to", "opportunities", "yes", "no", "profit", "median_cost", "gate_pass_share", "median_duration_s", "clipped_to_period"}}, "last_scan"}`. Opportunities are distinct events; profit is after the scanner's fees (sum of each event's best sighting); `gate_pass_share` = share of events whose best set cost is within `arb_scan_cap`; duration only for events seen in two scans or more.

**Periods (S4).** `GET /api/shadow/summary?period=<id|current|all>`, default `current`; `GET /api/shadow/episodes?period=...`, default `all`. Rule: an episode belongs to the period in which its bid was placed (`join_ts` in `[started_at, ended_at)`), wherever it settles. A window covering all history (`all`, or `current` while only Period 1 exists) serves the runner's cached summary unchanged; any other period is computed per request from the stored episodes (same projections and caps; own one-worker pool; cached 60 s per app). The arbitrage section is clipped the same way (events by last sighting; rolling windows start at the later of 7/30 days ago and the period start). New response fields: `period` (`{"spec", "id", "name", "started_at", "ended_at", "current", "label"}`, id `all` for no filter), `period_ok` (false when the period markers could not be read: zeroed numbers), `period_rule: "join_ts"`. An unknown or malformed period is 422.

## Sprint 2A-3 reliability fixes (2026-10-22; additive fields, estimate made honest)

**Episode fields (new, defaulted on read for old episodes):** `through_vol` (contracts traded strictly below our price on our side while the bid rested; null on old episodes), `capped` (bool), `cap_reason` (`series_cap|market_cap|open_cap|run_budget`|null), `interval` (minutes, 10), `fee_mode` (`maker|zero`|null; null scores as maker).

**Held position and caps (F1).** Each cycle reads the ended, unsettled episodes (`shadow_recent(SHADOW_HELD_SCAN=3000, "ended")`) and rebuilds the held position: central fill x price per episode, an unknown fill counted in full. Limits, as the real strategy applies them to the account: `ceiling = max_open_frac x shadow_capital` (config `max_open_frac`, never above the API ceiling; cloud setting `shadow_capital`, default 150, 20-100000); `headroom = max(0, min(run_budget, ceiling - held, capital - held))`, split evenly across series; a series whose held cost is at least `series_share_limit x ceiling` gets 0. The share comes from an OPTIONAL private data file `control_api/data/shadow_limits.json` (`{"series_share_limit": <number in (0, 1]>}`, env override `SHADOW_LIMITS_PATH`, at most 4 KB, read once per cycle in the worker); missing, unreadable, malformed (deep nesting included) or out of range = no per-series cap, as in the public repo. When a limit binds the strategy's `desired_quotes` is asked again with the capped budget, and the resting cost per series is checked against it (continuing bids first, then new ones in strategy order). A continuing bid over the limit ends `cancel`; a new bid the limits refuse is stored as a **capped episode** (`capped: true`, `cap_reason`, `trades_read: true`, `fill` all zero), tracked by key like any episode (it converts to a normal one when affordable) and never scored. Trades of episodes that ended in this cycle are read in the same cycle (within `SHADOW_MAX_TRADE_READS`) so the held position is current. The pass doc gains `capped_new`, `held_cost`, `held_markets`, `ceiling`, `headroom`, `series_capped`.

**Per-market cap (H2, optional, private).** The same limits file may hold a second key, `market_share_limit` (a number in (0, 1], a share of the same ceiling; same size, parsing and failure rules as `series_share_limit`: missing, unreadable, malformed or out of range = no market cap, which is the public repo and leaves every result unchanged, with no new pass-doc field). With a limit `L`, a market (one ticker, both sides together) may hold at most `L x ceiling` dollars: its held cost (central fill x price of ended, unsettled episodes, a bid cancelled this cycle counted in full) plus the cost of its resting bids. Checked after the series budget, in the same order (unseen bids, continuing bids, then new ones in strategy order). A continuing bid that no longer fits ends `cancel`; a new bid that does not fit is **sized down** to the largest count in 0.01-contract steps that fits (`int(room / price x 100) / 100`, the strategy's own floor, never rounded up); when the result is below one contract it is stored as a capped episode with `cap_reason: "market_cap"` (full intended count, never scored). A bid the series budget already refuses keeps its series/open/run reason. **Budget flow (the strategy's rule).** With a market cap in force the installed strategy's `desired_quotes` is asked one market at a time, in market-list order, with the series budget left; each quote is sized down as above and the series budget is debited by the cost actually taken (to the cent), a refused quote debits nothing, and sizing stops once less than $1 is left. So what a capped market cannot use flows to the later markets of the series, still bounded by their own cap, the series budget, `max_order` and the open-exposure headroom. Assumption: the strategy sizes markets in order from the budget it is given (a market asked alone returns what it would in the full call). A market that returns two quotes in one call is sized by the strategy with both uncapped costs debited (the only residual). There are no resting orders and no hysteresis in the shadow. A continuing bid stays while its market could still be quoted (each market asked alone with the whole series budget) and is then kept or ended by the flow, so a flowed-to market is not cancelled and re-joined every cycle. A sized-down bid keeps its size on later passes (it is a continuing bid, kept while held plus resting still fits), so identical passes cause no cancel or replacement. The pass doc gains `market_capped` (tickers sized down or refused, at most 50) only while a market cap is in force. The value and the strategy it mirrors stay in the private repo.

**Fills (F4, F8).** A trade-through: `hi = count`, `lo = clamp(vol_at_price + through_vol - q0, 0, count)`, `mid` halfway (old episodes with `through_vol` null keep the full count in all three). An episode ended by `cancel` owns `[join_ts, end_ts)`: a trade at exactly `end_ts` belongs to the next episode.

**Fee schedule (F7).** Optional private file `control_api/data/fee_schedule.json` (or env `FEE_SCHEDULE_PATH`), read once per cycle in the worker, at most 64 KB and 200 rules: `{"default": "maker"|"zero", "prefix_rules": [{"series_prefix": str, "mode": "zero"|"maker"}]}`. A market's series is its ticker before the first `-`; the first matching prefix wins, else `default`. Missing, unreadable or invalid file (deep nesting included): every series uses `maker`. New episodes record `fee_mode`; the headline, `by_series`, `by_cell`, `daily` and `by_event_day` use each episode's own mode; `headline_zero_fee` stays zero fee.

**Summary (new fields; existing ones keep their names).**
- `headline` and `headline_zero_fee` gain: `ci_reliable` (bool), `headline_status` (`too_early|ok`), `break_even_win_rate` (cost-weighted average price over central filled contracts, null without fills), `observed_win_rate` (share of central filled contracts that won), `n_settled_fills` (scored episodes with a central fill), `peak_held_capital` (peak cost of central fills held from `through_ts` for a trade-through, else `end_ts`, to `settled_ts`), `return_on_held` (central P&L / `peak_held_capital`, null when 0), `first_fill_per_market` (`{"cost", "pnl", "roi", "markets"}`: only the earliest-joined filled episode per ticker and side, central scenario).
- `pnl.ci90` and `roi.ci90` are **null while too early** (`ci_reliable: false`); once past the gate the day-clustered bootstrap resamples only close days with a filled episode.
- `peak_capital` keeps its name and means **peak resting bids** (capped episodes excluded).
- `status` gains `headline_status`, `capped_episodes` (capped episodes in the summary's input), `settled_days` (close days with a scored episode); `days_covered` and the 7-day gate now count only close days with a filled episode.
- Top level gains `day_basis: "close_day"` and `fee_modes` (`{"maker": n, "zero": n}`); `fee_mode` is `"maker"` unless some scored episode used the zero fee (`"per_series"`).
- Capped episodes are excluded from every figure except `status.capped_episodes`.

## Sprint 2A-3 wave 2: interval variants (off by default)

- **Switches.** Env `SHADOW_VARIANTS=true` (default off; read at startup for the loop and on every check) AND cloud setting `shadow_intervals` (subset of {5, 7, 10}, max 3, default `[10]`). The baseline is the existing shadow cycle (cadence `poll_minutes`, episodes and passes tagged `interval` 10, ids unchanged); each other listed cadence runs as a variant on its own clock (loop tick 30 s). With the env off nothing new runs, no cache is used, and the summary carries `variants_enabled: false`, `variants: []`, `variant_compare: []`.
- **Per variant.** Own open episodes, own held position and caps (F1 per cadence), own pass docs (`interval` field); episode id adds `|i<interval>` so cadences never share an episode. Trade reads and settlement are cadence-independent: whichever cycle runs drains the shared queues. Variants stop adding episodes once today's total reaches `SHADOW_VARIANT_NEW_SHARE` (0.5) of `SHADOW_DAILY_NEW_CAP`, so the baseline keeps priority. No arbitrage scan and no summary refresh in a variant cycle. A cadence removed from `shadow_intervals` has its open episodes ended `shadow_off` by the next baseline cycle.
- **Load guard.** A variant cycle is skipped while a real pass, Stop or another shadow cycle runs (`pass_running`, `stop_running`, `busy`; one asyncio lock for shadow cycles only, never a trading lock), when not leader (`standby`), with the stand-in installed (`standin`), or while the last shadow pass took longer than `SHADOW_VARIANT_LOAD_S` = 20 s (`load`). Same one-worker shadow executor and 60 s budget; Stop never waits on it.
- **Shared read cache.** While variants are on, every shadow cycle reads through `ReadCache` (60 s TTL, at most 1000 entries, expired entries pruned on every insert, oldest dropped first, deep copies, failures never cached, trades never cached since each window is read once) in front of the same `ReadOnlyMarketData`; the view exposes only the four read methods.
- **Summary.** The headline and every existing field use baseline (interval 10) episodes and passes only. New: `variants_enabled`; `variants`: `[{"interval", "baseline", "pnl": {lo,mid,hi}, "roi": {lo,mid,hi}, "fill_rate": {lo,mid,hi}, "central_fills", "settled_episodes", "n_settled_fills", "capped_episodes", "days_covered", "too_early", "headline_status", "peak_held_capital", "last_pass_ts", "pass_ok_pct"}]` (baseline first by interval order: 5, 7, 10); `variant_compare`: `[{"interval", "vs": 10, "days", "pnl_diff": {"mid", "ci90": [lo, hi]|null}, "roi_diff_mid", "fill_rate_diff_mid", "too_early", "ci_reliable", "reliability_note"}]`. `pnl_diff` is variant minus baseline central P&L, paired by close day over days with a fill in either cadence; `ci90` is a day-clustered bootstrap of that sum, null while either side is too early. Period filtering applies to every cadence. `GET /api/shadow/episodes` gains an optional `interval` filter.

## Hotfix: legacy episodes (2026-10-22)

- **Headline.** `build_summary` (the runner's cached summary and every period) computes the headline and every existing field (`days_covered`, the too-early gate, `by_series`, `by_cell`, `daily`, `by_event_day`, `day_stats`, `variants`) from methodology-2 episodes only. Pass health is unchanged.
